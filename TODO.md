## SEO: per-route meta tags

**Проблема.** Все SEO-теги живут статически в `index.html`, поэтому они одинаковы
для всех трёх маршрутов (`src/App.jsx`):

| URL | `<title>` / `description`, которые видит Google |
| --- | --- |
| `/` | верные |
| `/register` | теги главной |
| `/blog/:slug` | теги главной |

Это SPA: сервер на любой URL отдаёт один `index.html`, React дальше подставляет
компонент в `<div id="root">`. Заголовок статьи рисуется внутри компонента, а
`<head>` при этом не меняется.

**Последствия.**

- Статьи (`history-of-wing-chun`, `two-paths-of-one-art`) в выдаче показываются с
  заголовком и описанием академии — про их содержание ни слова.
- Превью при расшаривании ссылки на статью (WhatsApp, Facebook, Telegram) тоже
  показывает описание главной.
- `<link rel="canonical">` (`index.html:39`) жёстко указывает на
  `https://www.tecong.pl/` — то есть каждая страница заявляет Google, что она копия
  главной. Прямой сигнал не индексировать статьи отдельно. Это самое серьёзное из
  трёх.

**Варианты решения.**

1. `react-helmet-async` — менять `<head>` из React. Просто (~час работы), решает
   проблему для Google, который исполняет JS. Но соцсети превью не исправят:
   Facebook/WhatsApp читают только сырой HTML.
2. Пререндер при сборке (`vite-plugin-prerender`, либо переезд на Astro) — на
   выходе настоящие отдельные HTML-файлы со своими тегами. Работает везде,
   включая соцсети, но требует перестройки сборки.

Для трёх маршрутов разумно начать с варианта 1 — он снимает проблему с
`canonical`. Пререндер — если понадобятся корректные превью в мессенджерах.
